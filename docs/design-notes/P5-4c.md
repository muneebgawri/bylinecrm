# P5-4c — production environment: one deploy mechanism, blue/green, backups (design note)

**Card:** #162. Production at `https://crm.pinionnewswire.com` on the NewswireOS production VPS beside
staging (P5-4a) — the repository half; the server steps are in `docs/deploy/production.md` and are
performed by the coordinator. Closes doc 49 P5-4's "zero-downtime web release; backups".

## Decisions

- **One mechanism, one table.** `deploy/staging/` became `deploy/env/`; every script takes the
  environment name first and `lib.sh` is the only place an environment's URL, compose project,
  runtime directory, edge file name, web alias and memory caps are written. A second copy of the
  scripts for production would have drifted within a week. Staging **keeps** `/opt/bylinecrm-runtime`
  and its `staging.env` (`<env>.env` is the pattern): moving a live stack's data to match a naming
  scheme is risk for no return, and the table makes the exception explicit.
- **Blue/green on both tiers, with explicit upstreams, not DNS.** `api` and `web` each exist as
  `blue` and `green` compose services behind profiles. The web container's nginx names the api colour
  in an `upstream` block read from a bind-mounted file (`web-dynamic/api-upstream.conf`) and the edge
  names the web colour in its rendered include file. A cutover is therefore two graceful reloads:
  nginx's reload is atomic per worker (new workers use the new upstream, old workers finish their
  requests), so no request is dropped and no DNS cache window exists. The earlier per-request
  resolution of `api` (P5-4a) would have round-robined between an unhealthy new colour and the old
  one the moment the new container existed, and a drained container's address would have lingered in
  resolver caches for up to its validity — the DNS route was tried on paper and rejected.
- **The api drains.** `main.ts` enables Nest's shutdown hooks: SIGTERM closes the listener, lets
  in-flight requests finish and runs every service's `onModuleDestroy`/`onApplicationShutdown`
  (BullMQ workers, the outbox and mail relays, the Prisma pools). The compose services carry
  `stop_grace_period` 45 s (api) and 30 s with `SIGQUIT` (web — nginx's graceful signal). Two
  colours overlap for about a minute; every background worker is already safe to run twice (#111's
  two-relay tests; BullMQ claims each job once).
- **Migrations are expand-then-contract.** The live colour keeps serving against the new schema
  during the cutover, so a column or table is added in one release and the old one dropped in a
  later one. The runbook says so; this note is where the rule comes from.
- **Revert is the default on failure.** Until the edge has been switched, any failure puts the web
  upstream back on the live colour and removes the new colour (`trap`), and the live colour never
  stopped serving. The edge switch itself goes through `install-edge.sh`, whose test-and-restore
  pattern (P5-4a) is unchanged: a rendered file that fails `nginx -t` is replaced by the previous one
  before the release reverts.
- **Templates for the edge, rendered per environment and colour.** `edge-http.conf.tpl` and
  `edge-https.conf.tpl` carry three placeholders (`__HOST__`, `__ENV__`, `__WEB_UPSTREAM__`); the
  reviewed text is otherwise the P5-4a file. For production behind Cloudflare's proxy (one subdomain
  level, so Universal SSL covers it) nothing changes: the edge's http block already takes the
  visitor's address from `CF-Connecting-IP` for Cloudflare's ranges only, and the server block
  restricts nothing by IP.
- **Backups copy, never sync.** `backup.sh` writes pg_dump custom format (restorable table by table),
  the roles (RLS policies name `bylinecrm_app`) and the attachments, each under a `.part` name until
  complete; retention is 14 daily sets and 8 Sunday sets, applied by name locally and offsite; the
  offsite copy is of tonight's set only (a sync would carry the local sweep to R2). A missing rclone
  remote keeps the local backup and **fails** the unit — the NewswireOS lesson that a silent offsite
  gap is found during a restore. `restore.sh` restores into a scratch database and directory by
  default (the drill); `--into-live` asks for the environment name typed and is never scripted.
- **systemd template units** (`bylinecrm-backup@<env>`), 02:47 UTC after NewswireOS's own 02:17
  backup, `Persistent=true`; `install-backup.sh` copies the tooling to a stable path so the unit
  does not depend on which release directories are kept.
- **Production teardown is typed, not flagged.** `teardown.sh production` reads the word
  `production` from a terminal; stdin that is not a terminal is refused.
- **Release directories are shared** (`/opt/bylinecrm/releases/<sha>`): the files are identical
  for both environments. Pruning keeps the newest five releases of **every** environment.

## Tests

`deploy/env/test/run.sh` (CI's `pnpm test:deploy`), against the real scripts with a fake `docker`
and `rclone`: the #120 refusal for both environments (naming the environment's file and install
command); a first release in order (pull → check → migrate → api up/healthy → web pointed → web
up/serving → edge rendered and reloaded; nothing stopped; `ACTIVE_COLOUR=blue`); a second release
(green up, the running blue web reloaded onto `api-green` before green web starts, edge switched,
then blue stopped); revert when the new api never gets healthy (web upstream back, new colour
removed, old colour never stopped, lock released); revert when the edge refuses the rendered file
(previous file restored, no reload, no stop). `backup.test.sh`: dry run writes nothing; the set is
complete and `.part`-free; retention keeps a recent set and an old Sunday, prunes an old weekday
and an ancient Sunday; no rclone call without a remote and exit 1; with a remote, tonight's set is
copied by name and remote retention deletes by name, never syncs.

## Not in this package

The server steps themselves (the coordinator runs them); a separate worker process; Cloudflare's
proxy in front of production (a one-step switch described in the runbook, decided by the owner);
NewswireOS declaring `bylinecrm-edge` in its own compose (a NewswireOS change, PNW-551).
