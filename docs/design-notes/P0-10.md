# P0-10 — the route gate: accessibility and phone use on every page

Issue #38. Doc 48 FR-CRMS-UI-8 (WCAG 2.1 AA) and FR-CRMS-UI-12 (mobile-responsive, usable on a
phone — owner, 2026-10-09). The design system's gate (`packages/ui/gates`) checks components in
Storybook; nothing checked the pages the app is made of. This gate does.

## What is checked

Every state below, at **375px** (phone), **768px** (`BREAKPOINT_PX.mobile`, the first width with
the full layout) and **1280px**, in **light and dark** — six Playwright projects:

| Check                     | Where       | Fails when                                                                |
| ------------------------- | ----------- | ------------------------------------------------------------------------- |
| axe, WCAG 2.1 A + AA tags | every width | any violation                                                             |
| sideways scroll           | every width | `documentElement.scrollWidth > innerWidth`                                |
| primary action on screen  | every width | the visible `[data-primary-action]` element sticks out of the viewport    |
| touch targets             | phone       | a visible control is smaller than `--bc-touch-target` (44px) either way   |
| field text size           | phone       | a text field's text is below `--bc-touch-text` (16px; iOS zooms below it) |
| unanswered API call       | every width | the page asked for something the fixtures do not answer                   |
| screenshot                | phone       | any pixel differs from the committed baseline                             |

The touch and text sizes are read from the tokens on the page, so the gate and the components
share one definition. Exemptions, each written beside its code: axe's `aria-hidden-focus` while a
Radix modal is open (axe cannot see Radix's focus scope; the same exception as the design
system's gate); a link inside a sentence (WCAG 2.5.8's inline exception); an element 1px or
smaller (the `sr-only` pattern, not a target).

**States:** every entry in `src/routes/paths.ts`, plus the record drawer over a list
(`?open=person:<id>`, `?open=opportunity:<id>`) and the ⌘K palette open.

## How a new page is covered

`e2e/states.ts` builds its list from `paths`. `manifest.spec.tsx` holds `paths` and the route
manifest equal in both directions (the new case: every page the manifest declares is built by a
`paths` entry), so a page cannot exist without being visited. A record page (a builder taking a
second id) needs its example id in `RECORD_IDS`; without it the gate stops with the builder's name.

## The API and the session

Route interception (`e2e/api.ts`), not the Prism mock. Prism answers from the OpenAPI schemas
with values it invents, which would change the screenshots on every run, and the states worth
checking (a deal past its stage threshold, an unset field, a second workspace) have to be chosen,
not generated. Each GET the app makes is answered from
`e2e/fixtures.ts` — fixed ids, names, amounts and timestamps, typed against `src/api/types.ts` so a
shape the app stops reading fails `tsc`. The browser clock is fixed (`page.clock.setFixedTime`),
so relative times read the same. "Signed in" is `/api/me` answering 200 — what `RequireAuth`
reads — so no cookie or server is involved. A request with no fixture is answered 501 and fails
the state with its method and path.

## Running it

```
pnpm --filter web build
pnpm --filter web test:routes            # all six projects
pnpm --filter web test:routes --project phone-light
```

Findings print as one table (route × project) and, on GitHub, as the job summary. CI runs the gate
in two shards (`routes-shard`); `routes` passes only if both do, and is the name branch protection
lists.

## Baselines

Phone screenshots are made on the CI runner, never on a Mac (text rasterises differently). After
an intended visual change: push, then `pnpm --filter web routes:baseline` — the shared
`scripts/visual-baseline.mjs` (the design system's script, moved and parameterised, so there is
one) dispatches `ci.yml` with `baseline=true`, waits for the `routes-baseline` job, and copies the
`routes-baselines` artifact into `e2e/__snapshots__/`. Commit them with the change.

## Findings on main, and what fixed them

236 findings in the three light projects before any fix; 0 in all six after. The causes, each fixed
in the component responsible: the sidebar's workspace and account triggers and the top-bar search
named by an `aria-label` that hid their visible text (WCAG 2.5.3); inline-edit values named from
the raw value instead of what they show, and a profile link nested inside the edit button; a
`<dl>` holding a paragraph; board cards named without their visible text; loading regions with an
`aria-label` but no role; links inside sentences told apart by colour alone in dark mode; the
shell's content column not shrinking (a grid item is as wide as its content), and an `sr-only`
label in a table cell escaping the table's scroll container; and on phones, 25–39px controls —
inline-edit values, timeline chips, stage-move buttons, the drawer's close button, palette rows,
settings tabs, the table chrome's tabs, search and pager.

## Not covered here

Settings tables still render as tables that scroll inside their card on a phone; FR-CRMS-UI-12
asks for stacked cards (P1-UI-2 builds that pattern for people and companies). Drag-and-drop and
other interactions are the unit tests' job; this gate looks at each state at rest.
