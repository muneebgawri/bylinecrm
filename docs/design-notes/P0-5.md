# P0-5 — Design-system seed

**Package:** `packages/ui` (`@bylinecrm/ui`). **Spec:** doc 48 §10 (D-241), FR-CRMS-UI-6…10. **Issue:** #6.

## Token model

One file of values (`tokens.css`), one file of Tailwind mappings (`theme.css`), one TypeScript
module of attribute/storage names (`theme/theme.ts`). Theme and density are two attributes on
`<html>`; `system` and `comfortable` are the _absence_ of the attribute, so the OS preference
applies through the media query and there is no third state to keep in sync. The dark block is
written twice in CSS (media query and attribute) because CSS has no way to say "either", and
the two blocks sit adjacent so a value cannot drift between them.

Semantic names, not Pressboard's: the embed (P5-3) maps names at the boundary; this package does
not know NewswireOS exists.

## Why the palette is deleted

`--color-*: initial` in `@theme` removes every default Tailwind colour. Enforcing "tokens only"
by review would decay; enforcing it by removing the classes cannot. The cost is the trap the
README names (a palette class silently does nothing), which is why it is the first heading there.

## Components

Radix Primitives for behaviour (focus management, keyboard, ARIA), our markup and classes on
top. Shared pieces are single definitions: `cn()`, `focusRing`, `fieldClasses` (Input and
Textarea), `popoverSurface` (Select, DropdownMenu, Command), the Badge status vocabulary, and
`statusOf()` in the web app as the one mapping from a health state to a status. No enter/exit
animations in v1 — surfaces appear — which keeps screenshots deterministic and the UI quick.

`Button` uses Radix `Slottable` so `asChild` works with the loading spinner beside the child.
`DataTableShell` is layout only; TanStack rows arrive in P1-UI-2 and render into its body slot.

## The two gates

- **a11y:** `@storybook/test-runner` visits every story in the static build, injects axe, and
  checks `body` (not `#storybook-root`, so portalled dialogs and menus are seen) at WCAG 2.1 AA
  tags. A violation fails the job. No rule is disabled.
- **visual:** a Playwright spec generated from `storybook-static/index.json`, one test per story,
  `toHaveScreenshot` with `maxDiffPixels: 0`, animations disabled, caret hidden, fixed 1024×768
  viewport at 1× in Chromium. Snapshot path has no platform suffix: there is one baseline per
  story and it belongs to the CI runner.

Both jobs share `.github/actions/ui-browser` (Playwright Chromium + `fonts-inter`) with the
baseline workflow, so comparison and baseline are made in the same environment.

## Baseline procedure

`pnpm --filter @bylinecrm/ui visual:baseline` → dispatches `visual-baseline.yml` on the current
branch → waits → downloads the `visual-baselines` artifact into `__snapshots__/`. The developer
reviews the images and commits them in the PR that changed the pixels. CI's push from a
`GITHUB_TOKEN` would not trigger a new CI run, which is why the artifact round-trip is used rather
than a bot commit.

## Failure modes handled

Storage unavailable (private window): theme falls back to system and the choice still applies
for the page. Invalid stored value: ignored. Storybook build missing when `test:visual` runs: a
clear error naming the command. Missing scope on a tooltip trigger or dialog title: axe fails the
story, which is the intended place to learn it.

## Not handled here

The app shell, navigation and ⌘K wiring (P1-UI-1); data tables with real rows (P1-UI-2); a
`Form`/field-error composition (first UI package that needs a form); per-workspace accent/logo
theming (FR-CRMS-UI-9 — tokens are ready for it; the setting is a later package).

## Licence notes for the architect

- `axe-core` (MPL-2.0) added to `scripts/licence-exceptions.json` with its reason: the a11y gate
  mandated in the brief cannot run without it; dev-only, unmodified, not bundled.
- `http-server` was not used: it depends on `union@0.5.0`, whose package carries no licence
  field (reads as Unknown). `sirv-cli` (MIT throughout) serves the static build instead.
- Inter is not an npm dependency (`@fontsource-variable/inter` is OFL-1.1, off the allowlist). The
  token stack lists Inter first; CI installs the `fonts-inter` OS package so the product's
  typeface is what the gates render. If a self-hosted web font is wanted for end users, that is a
  reviewed OFL exception for the architect to decide.
- A shared `@bylinecrm/eslint-config` package now holds the ESLint floor; `apps/web` and
  `packages/ui` import it. `apps/api` still carries its own copy (out of this package's scope).
