# P0-19 — Initial bundle headroom (#131)

**Problem.** After P3-2 the initial JS was 188.84 of 190 kB (gzip). Every feature was spending the last
kilobyte, and the budget would soon be raised by default. The budget stays at 190 kB; what the first frame
does not need comes out of the first load.

**How it was measured.** A throwaway Vite config added a Rollup plugin that recorded each chunk's modules and
their rendered size, and the chunks were read from `dist/index.html` the way `.size-limit.js` reads them.
Three things were in the first load without the first frame needing them.

| What                                                                       | Why it was there                                                                                                                                   | Change                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The command palette (cmdk), the shortcuts sheet, the profile dialog        | `AppShell` imported them statically; they show only when opened                                                                                    | `lazy`, mounted on first open and kept mounted after (so closing still animates). The profile prompt after sign-up opens itself, so it loads then.                                                                                                                                                                                                                     |
| Every feature's hooks and endpoints (`api/queries.ts`, `api/endpoints.ts`) | The shell imports nine of them (session, account, workspaces, membership); Rollup assigns whole modules to chunks, so all of both files rode along | Split by feature, the pattern `mail.ts`, `settings.ts` and `sendingPool.ts` already followed: `team.ts`, `records.ts`, `deals.ts`, `templates.ts`, `mailAdmin.ts`; `sendingPool.ts` now holds its endpoints too. `queries.ts` keeps the cache keys, the client and the session/account hooks; `endpoints.ts` keeps the path helpers and the session/account endpoints. |
| `@bylinecrm/shared` (about 11 kB unminified of 33)                         | Built as one ESM file, so every export any page used sat in the chunk the first page loads                                                         | The ESM build is one file per source module (`bundle: false`) and the package says `sideEffects: false`; each module lands with the pages that use it. The API keeps one CommonJS file (`tsup.config.ts`).                                                                                                                                                             |

**Result.**

| Initial JS (gzip)     | Before    | After                 |
| --------------------- | --------- | --------------------- |
| total                 | 188.84 kB | 177.33 kB             |
| `index` (app + shell) | 33.5 kB   | 31.9 kB               |
| `queries` chunk       | 8.5 kB    | not in the first load |
| `Button` chunk        | 1.2 kB    | not in the first load |
| `vendor` (framework)  | 109.5 kB  | 109.5 kB              |

Headroom: 1.16 kB → 12.67 kB. FR-CRMS-UI-7 item 8 (the shell in the first frame, `directLoad.spec`) is
unchanged: the sidebar, top bar and route frame are still in `index`.

**Rules this leaves.**

- A hook or endpoint used only by lazy routes goes in its feature module, never in `queries.ts` /
  `endpoints.ts`. Those two hold what the shell needs: session, account, workspaces, membership, cache keys.
- An overlay the person opens (dialog, sheet, palette) is `lazy` and mounted on first open, unless the first
  frame shows it.
- `@bylinecrm/shared` stays free of top-level side effects (it declares `sideEffects: false`); a module that
  needs one must be listed in that field.
