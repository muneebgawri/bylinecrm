# P1-UI-5 — the web client typed from the generated OpenAPI schema

Issue #45. Doc 49 §0 (one definition), P1-1c (the OpenAPI document is derived from zod and
checked), P1-1d (one error envelope), P1-UI-6 (one `send()`).

## What changed

- `apps/web/src/api/schema.gen.ts` is generated by `openapi-typescript` from
  `apps/api/openapi.json` (`pnpm --filter web generate:api`). It is **not committed**
  (`.gitignore`), so it cannot drift from the document: `typecheck` and `build` regenerate it
  first, and `apps/web/turbo.json` adds `apps/api/openapi.json` to those tasks' inputs so a local
  turbo cache cannot replay a typecheck that passed against an older document.
- `src/api/types.ts` no longer contains a hand-written shape. Every type is an alias of a
  generated schema (`components['schemas'][…]`) or a path's parameters (`paths[…]`). The names
  call sites already used (`PersonView`, `BoardQuery`, …) stay as aliases; 47 hand-written
  interfaces/types were deleted, as was the stale committed `schema.d.ts` that nothing imported.
- The old file's own header said it: a change on the API side that was not mirrored there was
  caught by a browser walk, not the compiler. Now the web's typecheck catches it.

## One request function: `send()` kept, `openapi-fetch` not adopted

`openapi-fetch` types a call from the path string, which is attractive, but it would add a second
way to make a request (its own `fetch` wrapper) beside `client.ts`'s `send()`, which already owns
the base path, credentials, the CSRF header, multipart bodies, the 401 broadcast, file downloads
and the one error normaliser. Re-implementing those as `openapi-fetch` middleware would move the
same rules into a library's extension points for no gain at a call site: every endpoint is already
one function in `endpoints.ts` with typed inputs and a typed result. So the endpoint functions keep
calling `request<T>()`/`requestFile()`, and `T` is now a generated type. One request function, zero
runtime bytes from the schema (it is `import type` only, erased by the bundler).

## Request shapes: `Loose<T>`

The web compiles with `exactOptionalPropertyTypes`, and `openapi-typescript` writes an optional
field as `a?: T`, which rejects a present `undefined`. Call sites routinely build a body from form
state (`{ name: maybeName }`). What reaches the API is the same either way — bodies are
`JSON.stringify`d and query strings skip undefined — so request-side aliases (every `*Input`, the
board query) are `Loose<generated>`: an optional key may also be `undefined`, and arrays are
read-only because the client only reads them. Response types are never loosened.

## Pages

The three record page schemas differ only in `items`. `RecordPageOf<O>` is spelled as the shared
page fields plus `items: RecordViewOf<O>[]`, so a generic hook keeps which object it holds (a
conditional over three whole page types collapses to their union inside a generic). A type-only
assertion (`PageShapesAgree`) stops compiling if the API's page shapes ever differ beyond `items`.

## Money, one formatter for the product

P2-4 moved the money rules into `@bylinecrm/shared` (`formatMoneyIn`, used by the API when it
renders an email). The compact form and `toMinor` moved there too, so `apps/web/src/lib/money.ts`
holds no rule of its own: it supplies the reader's locale, the em dash for "no amount", and parsing
what a person types. A test asserts the web's output equals the shared function's for USD, JPY,
BHD and EUR in full and compact form, and pins the template render locale's output.

## How a contract break shows up

Renaming a response field in `openapi.json` (locally, not committed) and running
`pnpm --filter web typecheck` fails at every call site that reads the field — recorded in the PR.
CI runs that typecheck in the `typecheck` job; the API's own `contract:check` stays as it was.
