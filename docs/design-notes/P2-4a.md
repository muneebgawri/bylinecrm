# P2-4a — One country name; one field-error lookup (#76)

**Country.** The outreach footer printed the postal address's country as its ISO code (`US`) while the
mail-settings form and the editor preview showed the name. `packages/shared/src/templates.ts` now has
`countryName(code, locale = 'en')` (`Intl.DisplayNames`, falling back to the code) and
`formatPostalAddress(address, locale = 'en')`; the API's render (`templates/render/compose.ts`) and the
web's locked-footer preview both call `formatPostalAddress`, so the two cannot disagree. English for
both: the footer is rendered once for every recipient. The web's own `countryName` copy is removed
(`lib/countries.ts` keeps only the picker list, in the reader's language).

**Field errors.** `fieldErrorAt(error, path, { within? })` in `apps/web/src/api/client.ts` is the one
lookup of an API field error by path; `within` also matches anything under the path (`body` →
`body.content.1.text`). Every hand-written `fieldErrors.find(...)` is converted (SignUp, ResetPassword,
PlatformWorkspaces, InlineEdit's `messageFor`, the template body). `messageFor`'s old suffix match
(`beat` → `custom.beat`) is gone: every editor passes the full API path. Uses that are not a lookup by
path — "is there any field error", mapping all of them onto form fields, listing paths — are not lookups
and stay as they are.
