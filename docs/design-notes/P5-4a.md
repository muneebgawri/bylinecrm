# P5-4a — staging artefacts (design note)

**Card:** #84. Staging at `https://staging.crm.pinionnewswire.com` on the NewswireOS production VPS,
pulled forward from P5-4 (doc 49 §7 as amended). This package is the repository half; the server
steps are in `docs/deploy/staging.md` and are performed by the architect.

## Decisions

- **Images, not builds on the box.** CI (`images.yml`, push to `main` only, never PRs, not a
  required check) publishes `bylinecrm-api` and `bylinecrm-web` to GHCR tagged by commit and
  `:main`. Building on this box has starved NewswireOS production before.
- **One api image, two services.** `migrate` reuses the api image with a different command:
  `scripts/db-ensure-app-role.mjs` then `prisma migrate deploy`. That needs `prisma` and `pg` at
  runtime, so both moved into the api package's `dependencies`. The image is built with
  `pnpm deploy --prod`, runs as `node`, and its healthcheck requires `/health` to say `ok`
  (database, Redis and the RLS role all good), not merely 200.
- **The web container serves the app and forwards the API.** nginx inside it serves the Vite build
  (hashed assets cached a year, the shell never cached) and forwards `/api` and `/health` to `api`,
  resolved per request so it starts without the API. It passes the edge's `X-Forwarded-For` through
  unchanged: the API trusts exactly one hop, so the visitor must be the right-most entry, or every
  login would share one rate-limit bucket.
- **Shared edge, minimal coupling.** The NewswireOS edge includes
  `/opt/newswireos-runtime/nginx-dynamic/*.conf`, a runtime directory its deploys never clean. One
  file there, two stages (`edge-http.conf` before the certificate, `edge-https.conf` after), and a
  dedicated `bylinecrm-edge` network that only BylineCRM's `web` joins. No change to the pressboard or
  NewswireOS repositories is needed to go live; declaring the network in NewswireOS's compose is a
  durability follow-up for that repo.
- **Never break NewswireOS's `nginx -t`.** Its releases gate on it. `install-edge.sh` refuses during
  a NewswireOS deploy, refuses if the edge is already failing, and restores on failure; the edge file
  resolves BylineCRM per request so it never makes nginx depend on BylineCRM.
- **Hard memory caps** on every service (~1.5 GiB total); Redis `noeviction` because BullMQ jobs
  must not be dropped.
- **Base images from ECR Public's mirror** of Docker's official library — Docker Hub's anonymous
  limit blocked CI before (#79).
- **Secrets are generated on the server** by `bootstrap-secrets.sh` (idempotent, never prints,
  0600). The repository is public; it contains no example that could pass for a credential.

## Not in this package

The server steps themselves; production (its own server later, doc 48 §12); a separate worker
process (the workers run inside `api`; the env flags already allow splitting them out); zero-downtime
web releases (staging tolerates a restart of a 64 MiB nginx).

## Addendum (#90, 2026-10-11): the edge network is shared

The NewswireOS session declares `bylinecrm-edge` (external) on `newswireos-web-1` in its own compose and
creates the network if missing in its deploy script, so a fresh box, a restore or a BylineCRM teardown
can never fail a NewswireOS `compose up`. The consequence for BylineCRM: the network is not ours to remove.

- **Audit:** the compose file already declares it `external: true` (compose never creates or removes an
  external network); `release-remote.sh` only checks it exists; `deploy.sh`, `rollback.sh` and
  `install-edge.sh` never touch networks; no script runs `docker compose down` or `docker network rm`.
  Nothing needed changing.
- **`teardown.sh`:** removes the edge include file (test-and-restore, like `install-edge.sh`), the
  project's containers (found by the compose project label, so no release or sha is needed) and the
  project's own networks (also by label — the external network carries no project label, and the
  script skips it by name as well), and keeps data unless confirmed twice. It reports the shared
  network's members and never removes it. Proven against a local stand-in edge: refusals (no `--yes`,
  unconfirmed purge, NewswireOS lock), the failure path (restore, real error shown, edge healthy, no
  reload), and the success path (project gone, data kept, network kept with the edge still attached).
