# P2-2 — Gmail sync: import, incremental history, matching, timeline

Issue #55. Doc 48 FR-CRMS-2 and §6; doc 50 §A (mail on the record's timeline); parity ledger
`messaging` and `blocklist` rows (PAR-017, 022–030, 096). Builds on P2-1 (mailboxes, `MailboxTokens`),
P1-3 (timeline), P1-5 (BullMQ pattern), P1-1d (errors).

## Gmail behind one port

`GmailPort` (`gmail.port.ts`) has four methods — profile, list messages (a Gmail search), list history,
get one message in full — with Gmail's own shapes. `GmailHttp` is the only code that reads mail from
Google; tests bind `test/support/fake-gmail.ts`, which resolves access tokens through the fake OAuth (a
revoked grant is refused) and builds messages as Gmail returns them, so the real parser reads them.
**Deviation:** the card listed "get thread"; sync never needs it (history and lists name messages, and a
message names its thread), so it is not in the port.

## The run (`MailSyncService.syncMailbox`)

1. A mailbox that is not `connected` — or whose token Google refuses mid-run (`MailboxUnavailable`) — is
   **skipped**, and the state records why (`reconnect_needed` / `mailbox_disconnected`).
2. **First import** (no cursor yet): read the profile's history id, list `after:<now − 30 days>`, import.
3. **Incremental**: page through `history.list(startHistoryId, messageAdded)`, import the added ids.
4. **Recovery**: Gmail answers `404` for a cursor it no longer keeps; the run re-lists from the last good
   sync less a day (`MAIL_RESYNC_MARGIN_MS`), never further back than the first import's 30 days, and starts
   a new cursor from the profile. Mode `recovered`.
5. Success writes `idle`, the new cursor, `last_synced_at` and clears the error. A failure writes `failed`
   with a code (`gmail.<reason>` or `internal`, never a token or a Google body) and **rethrows**, so the
   queue retries the job; the next tick starts clean.

Importing a set of ids: ids already stored are dropped (one query per chunk); the rest are fetched
`GMAIL_FETCH_CONCURRENCY` (5) at a time per chunk of `GMAIL_LIST_PAGE_SIZE` (100); then **written one by
one, oldest first** — a thread's first message is the first stored, and no two writes of one run race.
A write that loses a race with another run (unique violation) is a duplicate, not an error.

**Passed over:** labels `DRAFT`, `SPAM`, `TRASH`, `CHAT`; and mail whose **every outside participant** (any
address other than the mailbox's) is covered by the workspace's blocklist or the mailbox owner's own
entries. Mail with one non-blocked outsider is imported. Entries apply from then on; stored mail stays.

**Direction:** outbound when the sender is the mailbox's address or Gmail labels it `SENT`.

## Quota and backoff (the constants)

| Constant                           | Value                               | Why                                                                                    |
| ---------------------------------- | ----------------------------------- | -------------------------------------------------------------------------------------- |
| `GMAIL_QUOTA_UNITS_PER_S`          | 200                                 | Gmail allows 250 units/user/s; the rest is left for the same mailbox's sending (P2-3). |
| `GMAIL_UNITS`                      | profile 1, list 5, history 2, get 5 | Gmail's published per-method costs.                                                    |
| `GMAIL_RETRY_ATTEMPTS`             | 5                                   | Per request, on 429 / 5xx / no answer only; anything else throws at once.              |
| `GMAIL_RETRY_BASE_MS` / `_CAP_MS`  | 1 s / 32 s                          | base · 2^(n−1), capped, ± 20 % jitter (`gmailRetryDelayMs`, one function).             |
| `GMAIL_HTTP_TIMEOUT_MS`            | 15 s                                | One request.                                                                           |
| `MAIL_SYNC_EVERY_MS`               | 2 min                               | The tick that enqueues every connected mailbox.                                        |
| `MAIL_SYNC_JOB_ATTEMPTS` / backoff | 3 / 30 s exponential                | A run that threw.                                                                      |
| `MAIL_INITIAL_SYNC_DAYS`           | 30                                  | How far the first import reaches.                                                      |

The quota is a one-second window per mailbox in Redis (`GmailQuota`), shared by every worker: a request
that would overrun waits for the next second instead of being throttled by Google. Every request takes
its token from `MailboxTokens.getAccessToken` at the moment it is sent (P2-1: refresh under a lock).

## Parsing and the one sanitiser

`parseGmailMessage` (pure) reads headers case-insensitively, decodes RFC 2047 words (`libmime`, MIT),
parses address lists including groups (`addressparser`, MIT), finds the first inline `text/plain` and
`text/html` parts depth first in their declared charset, and notes attachments. `html.ts` is the **one
sanitiser** for mail: an allowlist like P2-4's serializer (`sanitize-html`, MIT, configured with an
allowlist of tags and only `href`), with links kept only through P2-4's own `safeHref` (`https:` /
`mailto:`). **Images are dropped** — a remote image in received mail is the sender's read receipt. A
message without a text part gets one derived from the HTML. Each part is capped at
`MAIL_BODY_MAX_CHARS` (200 000) and marked `body_truncated`.

## Matching (PAR-028) and following people

An address belongs to the live person whose **primary** email it is (unique in the workspace), else to the
earliest-created person listing it as an **additional** email (case-insensitive); and to the member whose
sign-in email it is. One SQL subquery (`PERSON_FOR_ADDRESS`, `matching.ts`) serves import and re-matching.

`MailSyncSubscriber` re-matches on `person.created`, `person.restored`, `person.deleted`, and
`person.updated` when `emails` changed: every address the person has or had is re-pointed at whoever owns
it now — so earlier mail follows a person who gains an address, a deleted person's mail goes to whoever else
has the address (or no one), and a restored person gets it back. A workspace with no synced mail skips the
work entirely (one indexed check), so person writes cost mail sync nothing until a mailbox has synced.
**Contact auto-creation is off in v1** (ledger PAR-029, deviation): an unknown address is stored unmatched.

## Timeline (exactly once)

A message is announced as `email.received` / `email.sent` (new catalogue types, object `email`) only when
it is **newly stored**, with `targets` = each matched live person, their company, and the open deals they
are point of contact for, and `email` = an `EmailSummary` (ids, direction, subject, snippet, sender, sent-at,
`Message-ID`, `In-Reply-To`, `References`) — never the body. `email` joined `LINKED_OBJECTS`, so the timeline
subscriber writes one `linked-email.received|sent` entry on each target through P1-3's existing mechanism,
with the summary in `properties.email` and the subject as the linked name. Re-matching later does **not**
write entries for mail imported before the match: the mail appears in the person's thread list at once;
its timeline line is the import's. Webhooks deliver both events (with the summary).

P2-3 reads `inReplyTo` / `references` from the summary to detect replies and publish `email.replied`.

## Who sees what

- `GET /api/w/:id/mail/threads?target=<person|company|opportunity>:<id>` (`record:read`): threads with a
  participant who is the person, one of the company's live people, or the deal's point of contact, if the
  caller can read the target (`readableTargets`; else 404). Newest first, cursor.
- `GET /api/w/:id/mail/threads/:threadId` (`record:read`): the mailbox's **owner** sees everything; anyone
  else must be able to read a person the thread concerns (else 404) and then sees **bodies of a pool
  mailbox's mail**, and only **subject, snippet and participants of another member's personal mailbox**
  (`bodiesVisible: false`, bodies null). An admin is not the owner: privacy of a colleague's personal mail
  holds for admins too.
- `GET /api/w/:id/mailboxes/:id/sync` (`mailbox:read`, P2-1's mailbox visibility) and
  `POST …/sync` (`mailbox:manage`, owner or admin — `MailboxesService.assertChangeable`, added to P2-1's
  service so the rule stays there): `202` with `queued: false` when a run is already queued or running.
- `GET/POST /api/w/:id/mail/blocklist`, `DELETE …/:entryId` (`mailbox:read` / `mailbox:manage`): each sees
  the workspace's entries and their own; workspace entries are an admin's (403 otherwise); an API key has
  no personal list.

## Workers

`MAIL_SYNC_WORKER` (default `1`, like `WEBHOOK_WORKER`) runs the queue's worker in this process:
`mail-sync` jobs `sync` (id = mailbox id: one queued or running per mailbox) and a repeating `tick` that
enqueues every connected mailbox (read as the owner — a tick is no tenant's). `mailbox.connected` enqueues
the first import at once. The cross-tenant suite sets `MAIL_SYNC_WORKER=0` in its config: it drives sync
directly against the fake, and a worker started by any spec's app would otherwise call the real Gmail.

## Tests

- Unit: `parse-message.spec.ts`, `html.spec.ts` (XSS cases: scripts, handlers, `javascript:`/`data:`/
  protocol-relative links, images, SVG, comments), `retry.spec.ts`, `gmail.http.spec.ts`.
- Cross-tenant `mail-sync.spec.ts` (24): first import with paging, labels and the 30-day window;
  incremental, idempotent re-run, a message repeated in history stored once; expired-cursor recovery;
  429 retried with backoff; a failure recorded then cleared; a `reconnect_needed` mailbox skipped with its
  reason; the first import queued on connect; matching to person and member; re-match on create, delete,
  restore, and losing the address; the blocklist API and both scopes at import; one timeline entry per
  message per target with no body; owner vs colleague vs pool visibility; and workspace B reaching none of
  A's threads, lists, sync state or blocklist, its own mail matching nobody in A.
- Mutation-checked: disabling the blocklist rule or the body-hiding rule fails the suite.

## Not in v1

Deleting mail Gmail deleted (history `messagesDeleted`); label changes; Microsoft/IMAP; contact
auto-creation; timeline entries back-filled on a later match; attachments' bytes; Gmail push
notifications (the tick polls); removing already-stored mail when a blocklist entry is added.
