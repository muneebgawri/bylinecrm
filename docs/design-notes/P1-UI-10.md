# P1-UI-10 — exit-check polish, the profile name, the person-create fix

Issue #68, from the Phase 1 exit check (items 8–15, less 12, which P1-UI-8 owned), plus the
person-create defect P1-UI-9 found. Each fix's test was committed first and failed on `main`
(`e8c8013`; the failures are quoted in the PR).

## 8. A record URL opened directly drew no shell (FR-CRMS-UI-7)

Two things replaced the whole frame on a direct load. `RequireAuth` wrapped the workspace routes and
drew a bare skeleton while `/api/me` was pending; and the workspace route carried the only
`hydrateFallbackElement`, so while a lazy page's code loaded React Router drew that fallback **in
place of** `AppShell` (it renders the nearest fallback above the first unloaded lazy route).

- Every lazy page now carries its own fallback (`lazyPage()` in the manifest), so the code wait is
  drawn inside the shell's content area.
- The shell guards itself. `useAuthGate()` is the one rule (`/api/me`: pending, signed in, or a 401
  → sign-in with the return path; anything else is thrown to the boundary). `RequireAuth` (the
  workspace list) and `AppShell` both call it. The shell draws its frame immediately and shows the
  content skeleton until the person is known — the protected page itself still waits.
- `directLoad.spec.tsx` checks the sidebar and top bar are in the first committed frame with the
  API silent, and that the same sidebar node is still there once the answers arrive (no remount,
  so no jump).

## 9. Sidebar headings with nothing under them

Gating moved from each `NavEntry` to the group: `visibleItems(group, membership)`. While the
membership is unknown, a gated item is a `NavSkeleton` row of the same height (nothing shifts when
it resolves); once known, a group with no usable item is not drawn.

## 10. "Close date" meant two dates

`closeDate` is the date the deal is expected to close; `closedAt` the day it did. The label for
`closeDate` is **"Expected close"**, written once in the shared field descriptors
(`packages/shared/src/views.ts`), which the list columns, filters and exports already read.
`fieldLabel()` (the record page, forms, timeline chips) now falls back to those descriptors, so the
two label tables cannot disagree about a field the descriptors name; `closedAt` → "closed" is in
the web table because the descriptors don't describe it. A closed card reads "Closed Oct 9, 2026";
an open card's chip reads "Expected close Oct 31, 2026".

## 11. The display name — one per person

Members were named by their address's local part, stored per seat (`workspace_members.display_name`,
P1-1b) and, in the web app, re-derived from the email by a helper. The name is the person's:

- **`users.display_name`** is the one definition (migration `20261010000100_user_profile` carries
  each person's first seat name over and drops the seat column). Everything that names a member
  reads it: the members summary, the owner embedded on a row (P1-4a's `MEMBER_SUMMARY_SELECT`
  selects `user.displayName`), the members list, the template sender.
- **`GET/PATCH /api/me/profile`** (`displayName`, 1–80 characters, trimmed;
  `DISPLAY_NAME_MAX_LENGTH` in shared). It runs on the restricted client under `app.user_id`: a
  column-level `UPDATE` grant (the two profile columns and `updated_at`) and a `users` policy
  matching the caller's row. No owner-client write is added to a request path (P0-3's list stands).
- **`profile_completed_at`** records that the person confirmed their name. The shell asks once
  ("What should your team call you?", the suggestion prefilled); saving or dismissing — Esc, the
  scrim, "Not now" — saves the shown name, which confirms it, so it is asked once per person, not
  per device. "Edit profile" opens the same dialog from the user menu and the palette.
- A rename invalidates every cached query: names appear in rows, pickers and timelines everywhere,
  and a rename is rare.

## 13–15. Lists

- An identity cell's second line is dropped when it repeats a visible column (`sublineOf` knows
  which field it came from): a company's domain is no longer shown twice. Phone cards keep it — a
  phone has no columns.
- The list table's last data column takes the space left over, so the columns fill the card. A saved
  width stays the column's own; the spare is added only when drawing.
- `scrollbar-hidden` (`packages/ui` theme): the view tabs and the phone stage chips scroll without
  a visible bar. Touch, trackpad and wheel still scroll them, and keyboard focus scrolls a chip into
  view.

## Person create

`emails.additional` and `phones.additional` default to `[]`. The schema is shared by create and
update, and an update still replaces the whole object (P1-1a): leaving `additional` out of a
PATCH means none, as before.
