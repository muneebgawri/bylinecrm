# P1-UI-11 — Move-then-delete stages, restore fields, 44px small controls, the gate inside dialogs

Issue #75. Follows P1-UI-8 (settings screens) and P1-2b (stage delete with `moveDealsTo`, field restore).
Requirements: doc 48 FR-CRMS-9, FR-CRMS-UI-6, FR-CRMS-UI-12.

## Deleting a stage that holds deals

One dialog, two steps (`StageDeleteDialog`). The first is the plain "Delete X?". It sends the plain
`DELETE`; if the server refuses with `details: { liveDeals, trashedDeals }`, the same dialog becomes
"Move N deals (M in the trash) to another stage first." with a picker of the pipeline's **other open
stages** and one request, `DELETE …?moveDealsTo=<stageId>`. The counts are the server's answer, never a
client count (the board is owner-scoped and leaves out the trash). A won or lost stage is not offered —
a delete never closes deals, and the server refuses one anyway. Any other refusal (a rule points at the
stage, the last stage) and the 413 past the move limit are shown in the server's words. The success
toast names the count and both stages. Moved deals change stage, so the deal lists refetch with the
pipelines. This replaces P1-UI-8's "open this pipeline's deals" fallback.

`ApiError` now carries the envelope's `details` (P1-2b added it to `ApiErrorBody`); `detailNumber()` in
`api/client.ts` is the one way to read a numeric fact from it. `ConfirmDialog` gains `confirmDisabled`
(the move step waits for a target).

## Restoring an archived field

Admins get a Restore button on each archived field (`POST …/custom-fields/:id/restore`); a toast says it
is back. The archive confirmation no longer says it can't be restored. Others read the archived list
only.

## Small controls on a phone

`Switch` (a 36×20 track) and `Checkbox` (a 16px box) were 32×18 and 14×14 targets on a phone. Below
`md` the button now grows to `--bc-touch-target` around what it shows, and negative margins of the same
amount keep the layout exactly as before; desktop is unchanged. One definition, `lib/touch.ts`
(`phoneTouchArea.box` / `.track`), computed from the token. The visible part is a child span and the
focus ring moved onto it (`groupFocusRing`, added to the one focus module), so the ring still hugs the
track or box.

## The route gate checks inside dialogs

Pages mark the trigger of their main dialog with `data-primary-dialog` (ten pages: workspaces, the
settings create dialogs, people/companies, deals, templates). At 375px, after the page's own checks and
screenshot, the gate opens that dialog and runs the touch-target and field-text rules inside
`[role="dialog"]`, then closes it with Escape. A marked trigger that opens no dialog is a finding; a state
that already shows a dialog (the palette, a drawer) is checked as it stands. Radix's mirror input beside
each checkbox and switch (`aria-hidden`, `pointer-events: none`) is exempt with that reason: nobody can
touch it, and the control beside it is checked.
